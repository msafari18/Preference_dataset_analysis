Run the banking judge workflow in this workspace.

1. Run python3 scripts/prepare_judging.py. Read its validation report. If it fails, stop and report the specific file problems; do not judge stale tasks. If it passes, use only the manifest path printed by that run.
2. For each manifest task, launch a separate judge subagent if agent tools are available. Each subagent receives ONLY its input_file contents and output path. Do not give it prior discussion, another judge's output, the hidden label mapping, scenario labels, or the answer-generator identity. Process tasks in batches within the available concurrency limit. An agent is an isolated judging session, not a different underlying model.
3. Each judge follows the supplied rubric and writes exactly one JSON judgment to its designated output_file, assessing every candidate. Do not generate or alter candidate answers. Do not invent a preference if all candidates are unacceptable. Record the actual judge model identifier when available, execution date, and rubric/input hash in separate run metadata; never invent unavailable identifiers.
4. Check each output for valid JSON, exact question/candidate IDs, integer scores 1–5 or null, all required dimensions, and evidence/flags. Compute utility and review routing in code; do not rely solely on the judge's requires_human_review field. Route ANY flag, null score, factual or safety score below 4, generation truncation, or uncertain decision to review. Retain ties/exclusions explicitly.
5. Only propose a pair if the preferred answer passes factual and safety thresholds, has no unresolved flags, and the preference rationale supports a meaningful distinction. All flagged pairs remain provisional until human review. Do not call AI checking human validation. Select a seeded random 20% (rounded up) of otherwise unflagged question cases for human audit; report actual counts. Never mark a case human-reviewed automatically.
6. Save original agent judgments, label mappings, routing reasons, audit selection, and run metadata. Summarize proposed pairs, ties, exclusions, flagged cases, and human review workload. Do not train a model or implement the optional judge-feedback library.

If spawning agents is unavailable, report that limitation. Do not claim that ordinary ChatGPT created separate agents. Offer sequential independent chats using the prepared input files instead. This workflow does not require an API key when executed in an agent-enabled workspace, but model usage and limits still depend on that environment.
